# BlastIRC: flat messenger layout

## Scope and source of truth

The approved layout is one flat native window: a thin server-avatar rail, an expanded-name or compact-avatar channel sidebar, one active conversation, an independently collapsible right member list, and a simple bottom status bar. It replaces the previous split/docking workspace and the earlier HTML study. No tab bar, splits, floating panels, docking, drag-and-drop layout, or saved layout presets.

Telegram-style incoming/outgoing bubbles are the default. Each channel can independently use traditional aligned IRC rows; that preference survives restart. The shell has one modern presentation with explicit UI/message fonts and Noctalia semantic colors, not interchangeable interface presets.

The frontend remains native C++23 with the pinned Noctalia C++ library, Wayland/xdg-shell, EGL/GLES, and native text/IME controls. No Qt/QML, webview, X11, or parallel frontend. SDL3/SDL_mixer provide cue audio; libmpv handles supported local preview assets, not remote website embedding. Preserve existing IRC, storage, editing, effects, and capability boundaries.

Absent defaults stay absent until adjustment. Scale icons and hint/hit geometry from actual widths; keep user fonts unchanged. Capture the effective mode at drag start, retire content gestures without retiring the resize handle, and preserve preferred widths through responsive fitting.

Prioritize the viewed conversation, then explicit history/search requests over background startup work, then saved pin order and unread/recent chat activity; eligible muted/archived background conversations come last, but viewing one takes precedence. Reuse Pin/Unpin, not new scheduler preferences. Publish the visible selection before Core's first tick and reprioritize only unsent work on selection changes, without cancelling in-flight batches or bypassing server limits.

## Appearance and transparency

Use a continuous cohesive shell behind the titlebar, server rail, channel sidebar, and status, with very faint thin dividers between the two left bars and chat. Give chat breathing room with larger gaps, quiet selection, roughly 12-unit control and 16-unit bubble radii scaled once. Do not paint separate rounded card plates around the left bars/titlebar or add another frame inside the conversation. Compact layouts reclaim decoration before native controls/fonts. Native keyboard focus remains visibly distinct from selection.

A faint, non-hit-testable Outline Variant rule separates the buffer header from its messages. Scale its one-logical-unit thickness once with user zoom; retain the existing header and history allocations.

Colors come from semantic Noctalia roles: Surface/container variants, On Surface variants, Outline/Outline Variant, paired primary/secondary/tertiary containers, and distinct authored Hover/On Hover. Do not substitute tertiary for an authored hover role. No copied reference-app palette or hardcoded dark-theme foregrounds. Keep local template registration, XDG-aware generated output, built-in fallback, live reload, and invalid-palette recovery. Native primary controls preserve authored foregrounds when readable; otherwise use the existing contrast-safe palette fallback.

Honor Noctalia's resolved `pure_black_dark` surface ramp: black backdrop/surface with very-dark elevated containers, not a hardcoded replacement for every color. The live template receives the transformed palette; manual `--theme-json` generation must pass the effective `--pure-black` flag. Preserve authored accents, foregrounds, and hover roles, and never darken the resolved output twice.

Transparency is explicitly off by default. The saved opacity is an intensity used only when transparency is enabled. Apply transparency to background fills across shell panels, bubbles, composer controls, menus, and dialogs; text, icons, and focus marks remain opaque. Do not use whole-node/window opacity. Account for stacked background layers rather than claiming equal final transparency from identical alpha values. No desktop capture. Compositor support is required; low opacity cannot guarantee contrast over arbitrary wallpaper.

Unread badges use solid opaque primary plates, distinct error plates for mentions, and rounded-square backgrounds (roughly four logical units of radius). Repair paired foregrounds against the resolved plate for readable contrast, independent of surface transparency. Cover expanded/compact conversations and server counts without changing member privilege badges.

Interface scale `I` and Message text scale `M` are independent, each 0.7–2.0 with default 1.0, preserving existing UI/message font families. Chrome uses `I`; message body and metadata use `M`. Bubble body size is `14 × M`, dense IRC/utility size is `15 × M`, and Input matches the actual active buffer's font and size rather than `I`. Apply each logical scale once. Output DPR belongs to the native renderer and must not be applied again or conflated with either setting. Shape, measure, and paint with native font metrics instead of stretching cached glyph bitmaps; preserve font and color-emoji fallback.

UI and message typeface weights are independent saved settings (`appearance.ui_font_weight`, `appearance.message_font_weight`), both default 400, with Light 300, Regular 400, Medium 500, Semibold 600 and Bold 700 choices in Appearance → Fonts. Refresh native controls, popup options, measurement and reflow live without altering families, scales, drafts, selection, emoji or explicit emphasis. The composer follows message weight. Native popup requests carry the complete `TextFont` through sizing, painting and submenus; omitted fonts retain the library's normal defaults without BlastIRC settings dependencies.

## Navigation, identity, and persistence

Stable buffer IDs, not displayed targets or aliases, identify conversations and preferences. An editable cosmetic server alias must not rename the network-map key or its buffers. Server avatar paths are trusted local configuration; missing/unreadable images fall back to initials.

Use the shared model caption resolver for all normal network labels: preserve an explicit alias, otherwise resolve the managed child's live parent-catalog name, falling back to neutral Network. Preserve ambiguous existing aliases; never guess their provenance or rewrite stable keys. Refresh open palettes, materialized Mentions, topic titles and upload captions on naming changes. Search may retain routing-key metadata, but rendered captions must not expose it.

Channel avatars come from the IRCv3 registered [`avatar` metadata key](https://ircv3.net/registry#channel-metadata) using [`draft/metadata-2`](https://ircv3.net/specs/extensions/metadata) with its required `batch` capability. Handle notifications, lookup/deletion numerics, late capability changes, and deferred synchronization without treating metadata as chat. Accept only actual joined channels on their own network; preserve casefold/rename/merge and reject stale session/URL/request completions. Disabling avatars or losing the required capabilities clears displayed remote images.

An asynchronous bounded worker fetches public HTTPS URLs with `{size}=64`, verified TLS, no ambient proxy/credentials/cookies/referrer, no redirects, animation, decompression, or automatic retries. Enabling avatars exposes viewer IP and request timing to third-party image hosts; the existing Avatars preference disables loading. Resource limits are 32 admitted requests/results, 64 private session-cache files, 1 MiB combined response headers/body, and 1024-pixel axes/1,048,576 pixels. Queue/cache pressure defers admission, not a permanent failure or repeated HTTP retry. Raster preflight accepts bounded PNG/JPEG/static WebP; it is not a decoder sandbox or full pixel validation.

Only internally produced trusted `Buffer::avatarPath` files reach the channel view, never raw metadata URLs or server-supplied local/data paths. Route validated raster bytes directly through raster decoding rather than the native file loader's SVG heuristic, and downsample before retaining avatar textures. Decode/fetch failures restore initials; draft badges never replace those initials. Cache contents are session-only; offline/restarted views fall back until fresh metadata is synchronized. Do not add a contact service.

Keep configured server groups. Order conversations by global saved pin rank first (newest pin first), then a Friends group containing only unpinned friend DMs, then actual received/own chat and `/me` activity, not typing, presence, unread changes, or loaded history. Persistent Pin/Unpin uses the native pin glyph, not a Pinned subtitle; pinned friend DMs retain one friend indicator. Sidebar search and All/Unread/DMs filters operate on loaded local state, combine, and never fetch history, select another conversation, or mark it read. Keep the active conversation visible when regular filtering excludes it, except archived chats stay excluded. Identify its owning network if different from the browsed server. Distinguish this exception from actual matches and keep Clear filters available. Expanded filters and the compact selector expose Archived recovery; opening an archived chat does not unarchive it. Size filter buttons to their natural captions, preserving the Archived unread count, and use the existing selector when the row is too narrow. Exclude archives from normal lists and Avy. Preserve archived unread counts in recovery and global/server aggregates, honest draft indicators, and bounded draft-first/message-fallback tooltips.

The rail @ action opens a synthetic read-only global Mentions view, newest first, across retained received channel/DM mentions; exclude own, deleted, and presence entries. Preserve positive classifications across nickname changes; backfill legacy unclassified history only with a known current source nickname and source IRC casemapping. Show actor, friendly network alias, and conversation, omitting internal soju IDs without changing routing identity. Do not force a mention accent, border, or background merely because the row mentions our nick; retain classification for aggregation. A normal body left-click, actor/source activation, or Open original jumps to the retained source without changing drafts or acknowledging sources as read. Preserve text dragging, links, and context menus. Resolve current source identity/readability for every action, copy, quote, and media request; missing/stale/concealed source content must not leak, and the source's Fools override governs aggregate rows. Ordinary conversations expose a vertical up / plain unread-count button / down navigator only while eligible unread mentions exist in the current conversation. Arrows disable at the ends and never wrap; navigation does not mark read and preserves drafts and IME. The count button and its tooltip describe Core's mark-current-conversation-read action: clear all its unread messages, including mentions, advance its read marker, and leave other conversations unchanged. Never use an @ count or navigate all retained mentions.

Channel/query context and overflow menus provide icon-labelled Mute/Unmute and Archive/Unarchive actions bound to the source buffer, not current focus. Mute gates notifications and sounds only: unread counts, visual effects and retained data remain unchanged; Fools remains the stricter independent policy. Archive changes local navigation only, preserving join, connection, drafts, history and read markers. Only eligible new live incoming, non-own, non-fool chat restores an unmuted archived conversation; muted chats stay archived. History hydration/replay and own sends never restore it. Unmuting alone does not restore it. SQLite schema 9 persists both flags, defaults false for older databases, and merges mute with OR/archive with AND on buffer collisions.

Muted conversations use a bell-off glyph. Overflow menus display friendly network names without internal soju IDs; stable routing keys remain unchanged.

Save active selection, last conversation per server, and sidebar preferences. Retain per-buffer native editing, undo, reply, and transcript state without tab order. Remove obsolete tab/split/docking/floating layout metadata and commands; keep unrelated native dialog metadata. Only the active conversation enters visibility publication.

Observe arrivals before Core renames while the source is intact, then baseline imported rows after a collision. Synchronous post-migration remapping updates routes, message-style preferences, native documents, transcript caches, sidebar/member state, pending UI intents, and durable draft/read/pending data before same-tick persistence. Case-only changes preserve identity; merge collisions retain selected-conversation and draft-recovery semantics.

## Composer, settings, and members

The native Input remains the sole raw-document, caret, undo, selection, and IME authority across conversation changes. ## Link and media previews

Links, images, and media independently use Off/Click to load/Automatic, default Click to load (`[previews]` tokens `off`, `click`, `automatic`). Direct image/audio/video previews retain their load/error tiles and title-or-URL captions. Only an actually loaded, visible direct-media preview may replace a URL-only body, preserving raw copy and surrounding text. Images, including link thumbnails, open the image viewer; audio/video opens the player. Keep separate View image/Open player buttons absent; visible preview menus retain Info with the selectable original URL and known metadata, Copy and Open Link. Automatic still respects the independently configured destination type, including metadata images. Concealed fool rows admit no request; activation revalidates source access, and live readability guards retire visible previews/popouts when access changes.

Image activation opens the real in-app viewer with keyboard/Escape/focus restoration. Supported audio/video file assets open the shared player paused, with explicit play/pause, seek, volume, elapsed/duration and close; never autoplay or substitute an external browser for the player. Close and source/buffer/message invalidation stop/release playback. Only admitted downloaded file assets reach libmpv, never remote URLs; playlists and unsupported formats remain unsupported, not generic internet-video embeds.

Decode bounded PNG/JPEG and static WebP, and show a static first frame for GIF. Reject APNG and animated WebP explicitly rather than fabricating support. HTML previews expose known metadata through Info. Failed requests show available HTTP status and reason.

Canonical HTTPS `www.youtube.com/watch?v=…` links use YouTube's fixed official oEmbed endpoint instead of downloading the watch page. It never disables TLS verification. Fetching reveals viewer IP and timing; disclose that before automatic loading. Parse bounded HTML with libxml2 without external resources/entities; validate raster magic/dimensions before native decode. ## Soju lifecycle and management

Use a separate control client and independent enabled child clients, inheriting the physical endpoint and account credentials without duplicating secrets. Preserve stable local profile/buffer keys when adopting existing bindings; remote names are mutable display labels, not identities. Ambiguous legacy username/network selectors require explicit association.

Only current-session, completed control catalogs authorize child attachment. Merge partial attributes, remove empty attributes, distinguish empty completed discovery from disconnected/failed discovery, and reject stale events. Registration-time BIND rejection is fatal, including a following welcome in the same read. Root management commands use real acknowledgements and FAIL correlation, with sanitized credential-bearing fields.

Native Settings supports account and remote network creation/editing/deletion and local attachment toggles. Resolve callbacks by stable profile key, not a mutable vector index. Unavailable edit targets remain EDIT errors, never create forms. Parent disconnection stops its local children; child disconnection changes local attachment intent, not the remote upstream. Remote deletion retains local history, drafts, reads and pending-send recovery.

Treat `soju.im/FILEHOST` as session-scoped ISUPPORT, not CAP. Clear/revalidate authorization on reconnect, advertisement removal, configuration or credential change. Default trust is the physical parent hostname or boundary-aware subdomains; any additional trusted hostname is exact and explicitly configured. Never forward credentials to arbitrary IRC-advertised authorities or redirects.

The trusted FILEHOST receives the parent account's actual username and password through HTTP Basic authentication. Trusting an additional hostname grants it those credentials, not just permission to receive files. Require live authenticated account/child sessions and a configured account password; EXTERNAL-only authentication without a password cannot use FILEHOST. An unavailable soju host must not silently fall back to a public service.

## Verification contract

The UI dependency is the maintained [Noctalia library](vendor/noctalia/lib) in tracked `vendor/noctalia`, consumed directly by Meson and Nix with `library_only=true`; BlastIRC owns its asset and license installation paths and app-specific behavior. There is no external SDK download, copy, or root build-file replacement.

The vendored source originated at public [fork](https://github.com/trevarj/noctalia) revision `ad60f4c2a8841ce25c78f9d6ac8c111523fa34b6`, including 14 focused signed commits over the unchanged [Noctalia upstream](https://github.com/noctalia-dev/noctalia) base `5e4aae910b764c7aeee411f741a266263f104375` and generic scroll-into-view using the public border-aware viewport. BlastIRC's `main` tracks the source snapshot without importing SDK Git ancestry. Edit `vendor/noctalia` directly and commit UI changes with the app using signed commits (`git commit -S`); preserve upstream author attribution, identity, MIT license, credits, and source revision references.

For selective upstream updates, configure `noctalia-upstream` to `https://github.com/noctalia-dev/noctalia.git`, fetch it, and review each candidate and its dependencies before importing:

```sh
git fetch noctalia-upstream
git format-patch -1 --stdout <reviewed-commit> | git am -S --directory=vendor/noctalia
```

This retains the selected commit's author attribution while recording a signed app commit under `vendor/noctalia`. The tracked source is authoritative; no fork push or paired archive/hash update is required.

For a fresh checkout, configure and build in the pinned development environment:

```sh
nix develop .
meson setup build-native --wrap-mode=nodownload \
  -Dfont_dir="$BLASTIRC_FONT_DIR" -Demoji_dir="$BLASTIRC_EMOJI_DIR" \
  -Ddictionary_dir="$BLASTIRC_SPELL_DICT_DIR"
meson compile -C build-native
meson test -C build-native --num-processes 1 --print-errorlogs
```

Existing builds normally regenerate automatically; when migrating a build directory from `subprojects/` to `vendor/`, rerun the setup command with `--wipe` to discard cached subproject paths and options.
